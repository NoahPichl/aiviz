Reflect on the experience with AI

The prompts can be found in file: prompts.txt
At the beginning, the prompt (1) was used, where the problem was introduced as it is and the LLM was asked to help with brainstorming.    
Some AI-generated suggestions were also helpful and gave insights into how the code should be written to avoid incorrect comparison due to the size difference in datasets. Other suggestions were not necessarily accepted, because the LLM would go on and on about things that were not "important" at that time in the "conversation". For example, when using the prompt (2) we forgot to add the fact that we are not using the ground truth, only the metrics and predictions and the LLM would insist on adding the ground truth or would even modify the code such that "y-true" and "y-pred" were needed.  
We also tried to code with the help of AI, giving it prompts like (3) and (4). What we observed was that different LLMs focused on different things and if you forgot to give all the details that you already knew (i.e: shapes, files) it would ask you about all these different things and you have to answer again and again to some things that you already know but forgot to give, until you run out of time/credits. We tried to continue the code started by one LLM to another, but each time they would contradict each other. For example, Gemini started with Quantile crossing, Uncertainty Explosion and Prediction Autocorrelation Delay, stating that they would be enough to prove bias/hallucination in a model. However, they are not enough, and a lot of things can influence them. When the idea and code were further given to another LLM, it stated the same thing as we did, that it was not enough. After rerunning the same prompt in a new Gemini chat, the LLM changed its statement. This goes to show that everything given by AI should be further investigated and taken with a grain of salt. 
Another problem with the suggestions is the jump from idea to idea. We started with a solid idea and as we were brainstorming with the AI, we ended up losing our original idea and had a bunch of other ideas and no idea where to start implementing and what would work or not. When working with AI you get many ideas and explanations to the point it is too much to assimilate.  
We accepted the suggestion to compare the performance based on median MASE, even though we knew we cannot evaluate the performance of a model based only on one value. We thought it would be interesting to see what the Human-only pair chose and if it is something different, how would the result differ.
We also accepted some of the analysis done by Gemini and it can be seen in our notebook some statements that claim more than the plots show. 
As for failures, LLMs cannot always distinguish between the lines or blocks and it leads to false reports. For example: this picture was used to analyze the results and the model is insisting that the Global_Price dataset has a feat_seasonal_strength of almost 0.0. I corrected it by saying: “But global_price has a high feat_trend_strength and for x and e entropy the values are around 0.4-0.6 and it is the 3rd in worst performing” and the response was “Looking closely at the Global_Price row in the heatmap (plot_feature_profile), notice that while feat_trend_strength is bright yellow/green, feat_seasonal_strength is dark  purple( 
~0.0).”  
Another failure found while analyzing was for the feature profile within the short term series. We asked the LLM to analyze this heatmap and the response was: R “However, the 31 series comprising the noise group (Cluster -1) expose the model's primary short-term vulnerability: characterized by extreme ARCH effects and trend strength, this group suffers a median MASE of 1.10, failing to beat the naive baseline while exhibiting explosive uncertainty growth. “  
Q: what is this? (this was a reply to the “extreme ARCH effects”)
R: “When looking at the cluster profile heatmap for Cluster -1 (the short-term noise group), the e_arch_lm feature has a z-score of +2.3. This means the time series in that cluster have an ARCH statistic that is 2.3 standard deviations above the global average. Your feature extractor explicitly flagged them as having high conditional heteroskedasticity (volatility clustering). “. 
In the heatmap, it is clear that 2.3 actually corresponds to trend strength, not arch and if not careful, hallucinations can be introduced.  
Best practice found for using AI effectively during visualization and model analysis was to send the code for the visualization, alongside the visualization and explain what you are seeing and why you think that is or maybe say "this is what I am seeing, why?" And then the LLM, in most cases, would correct or add to our explanation.  
Also, sometimes the LLMs propose a very long code which usually is correct but still it is very complicated so it is quite hard to change it easily.
